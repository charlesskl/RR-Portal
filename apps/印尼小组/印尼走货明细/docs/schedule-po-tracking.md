# 排期 PO 物料走货追踪

排期「本周明细」「未下单」「新增」中的订单 PO 可点击，打开物料追踪抽屉。按采购明细列出物料、规格、采购单、供应商、采购单位、采购量、到货、已走货、待出运、还需走货及状态。展开物料可看到货柜、走货单 ID、出库批次、日期、实际数量和核对原因。删除的排期行不提供当前排期的查询入口。

## 关联范围

- 订单 PO、客户、RRI/RRM 来源、完整货号必须匹配所选排期。同一 PO/货号的累计记录不会因多个周次重复出现而重复累加，也不会按点击的排期行数量推算走货量。
- 订单 PO 按完整的分号分隔值匹配，不能使用包含查询。完整复合货号中的斜杠不拆分；采购编辑器明确用 ` / ` 合并的多个货号保留歧义。
- 采购明细 ID → 出库 `po_item_id` → 货柜行 `outbound_id` 是统计依据。只累加货柜行实际分配数量，不把整笔出库数量重复计入每个货柜。入库、出库分别聚合后查询，避免关联多条入库记录时成倍增加走货数量。
- 原采购单号 `source_po_no` 用于合并采购单后的来源辨识；IRRI/IRRM 只能辅助辨识来源，不能推断客户。多个客户或来源共用相同键、多个 PO/货号共用明细但没有各自分配数量时，显示待核对/分配，不自动按比例拆分。
- 缺少排期 PO 的同货号采购明细列为待关联候选，不计为本 PO 的采购量/到货量。未通过具体出库批次关联的历史货柜记录可作为核对参考，不猜测其归属或计入数量。

## 数量口径

- `shipped`、`arrived` 计入已走货；`loaded` 计入待出运；草稿仅在记录中显示，不参与已走货、待出运及正品备品分配。
- 还需走货（正品）= `max(采购量 − 已走正品数量, 0)`。待出运仍包含在还需走货中。各行使用自己的采购单位，不跨单位相加，不用申报重量替代件数。
- 入库正品和备品直接读取 `po_receipts`。旧出库/货柜表没有逐批备品标记，因此正品/备品采用明确的派生口径：先对已出运、已到港记录分配累计入库正品，再分配已装箱记录，超出正品部分记入备品；同一类记录按走货单及明细 ID 顺序分配。这是数量查看口径，不修改实际业务记录、单价或计费逻辑。
- 关联缺失、物料或数量单位不一致、出库分配超量、入库不足以解释正品/备品、缺失数量及未知状态均显示待核对。不能确认的走货量、备品量和剩余量用 `null` / `—` 表示，不当作零或已走齐。草稿的问题在记录中保留，但不单独影响已完成业务的统计。
- 没有可关联采购明细时显示空状态；手动标记已下单不会虚构采购或走货数量。

## 接口和权限

`GET /api/schedules/{id}/po-tracking?order_no=…&code=…&source=…`

使用现有排期模块访问权限，不要求编辑权限，不返回采购价格、金额或图片。服务端先核实所选 PO/货号/来源属于该排期，再在一个 repeatable-read 事务中读取关联资料；无建表、更新、自动回填或迁移。客户端切换 PO、关闭抽屉、刷新时废弃旧请求，错误显示可重试状态，不用空数据冒充成功。

验证包括纯数量/来源判断测试、隔离 PostgreSQL 接口测试（校验查询前后数据完全相同）、真实前端请求生命周期及排期入口绑定测试。
