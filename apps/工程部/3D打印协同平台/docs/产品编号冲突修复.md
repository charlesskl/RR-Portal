# 产品编号冲突修复（2026-10-19）

两边分别新增产品时都使用递增数字编号，导致不同产品同时占用 658、659。旧处理页只能选择一边，整轮同步也因此被阻塞。

## 本次变更

新增“保留双方产品（原系统产品分配新编号）”选项，仅用于上次共同版本中不存在、双方都存在的产品。已有共同产品的编辑冲突仍逐项核对。

新平台产品保留编号，避免改变云端订单任务和独立产品附件的既有归属。原系统冲突产品获得高于两边现有产品编号的新数字编号；其业务 JSON 中的 productId 引用随之更新，名称及内嵌图片保留。实际新编号以当次双方目录为准，不能预先假定为 660、661。

处理选择绑定当前差异签名；资料改变后过期选择失效。云端事务保存重编号映射及回执，响应丢失或桥接重启不会重复创建产品。若写回前现场另建产品占用目标编号，会停止处理并报错，不能覆盖该产品。

独立模型/附件文件仍不属于业务 JSON 同步范围。本次不移动原系统磁盘上的附件；若原系统按产品编号保存独立附件，须在执行“保留双方”前核对并制定对应附件迁移。新平台既有附件编号不改变。

## 部署

本修复包只需更新云端项目中的以下文件：

- shared/business-sync.cjs
- production/business-sync.cjs
- cloud/public/business-sync.js

正式 RR-Portal 通过 PR 合并到 main 后，由 GitHub Actions 的差异部署流程更新 printlink 服务。部署前按现有流程备份生产数据；管理员检查部署结果、服务健康状态及页面新选项。不要另外并行执行手动 Compose 部署，不要删除数据卷或覆盖现场配置、SQLite 数据库。

已安装全业务双向同步适配器的 Windows 桥接无需为本次新增选择重新安装；写回使用原有 CAS 和业务快照接口。若以后重装适配器，可使用更新后的 shared/business-sync.cjs。

## 本次现场处理

管理员刷新新平台“双向同步”页面，确认出现新选项后：

1. 产品 658 和 659：分别选择“保留双方产品（原系统产品分配新编号）”。
2. 光敏树脂8361F、灰色PETG 的库存：选择“使用原 3d-server 值”。用户已确认所有真实出入库只在原系统记账；采用当前最新余额，不手填旧截图数值。
3. 10 月 14 日机台 8、9、10 的三条“节龙分段”记录：选择“使用原 3d-server 值”，保留用户确认的删除标记。
4. 保存选择，等待桥接后续一轮；如差异发生变化，刷新并重新核对变化项。
5. 确认 Windows 控制台成功时间更新、错误清除；两边均能找到四个不同产品；三条无效记录保持删除；库存一致；新平台 10 月 16 日的有效每日记录与原系统逐条对应。
